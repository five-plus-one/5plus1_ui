日期：2026-10-20。组件库版本：0.4.1。

## 结论与范围

**课栈所需展示组件尚未全部完成抽取和重新设计。** 基础组件、编辑核心和多种工作区视图已经存在，但通用工作台、插槽及相近组件不能替代原界面的完整能力。

本轮重新核对了源文件清单，并对窗口、正文排版、异常恢复及下列重点模块进行了源码与接口对照。它属于完整清单核对加重点能力复核，不是全部组件所有交互状态的最终验收。

## 本轮完成的设计与行为

- **窗口控制**：标题位于左侧，附加操作、最小化、全屏与关闭依次位于右侧，关闭按钮位于最右上角。按钮保持可见，支持键盘聚焦和激活；操作按钮不会触发标题栏拖动。触摸设备使用 44px 点击区域。
- **窗口边界**：拖动、调整大小及容器变窄时限制窗口位置和尺寸，保持完整标题栏在可视区域内。全屏与还原、关闭与重新打开均作浏览器操作验证。
- **阅读间距**：Markdown 阅读、富文本编辑和协作编辑的正文共用纵向节奏。16px 正文使用 1.9 行高；段落间距 16px，章节前距 32px，表格、引用和语义块前后 24px，列表项间距 8px。表格单元格使用 12px / 16px 内边距；列表内段落保持较紧凑的层级。
- **内容分组**：设置表单字段组间距 24px、标签与控件 8px，内容与底部操作区间隔 24px。桌面卡片内边距 24px，窄屏 20px。调整针对内容关系，不放大标签和工具栏按钮。
- **概念折叠卡片**：底部留白位于折叠裁剪区域内部，随内容一起展开与收起。
- **图片状态**：加载失败后更换地址可恢复显示，错误回调交给调用方；Figure 复用正文图片占位，保留图注与来源。Markdown 图片卡片传递来源属性。
- **局部内容恢复**：新增 SurfaceBoundary，隔离内容渲染异常，提供重新打开和文档切换恢复；开发诊断通过回调处理，界面显示自然的恢复说明。
- **示例标注**：组件页以交互示例和接口说明表达能力；完整课栈功能的验收由本报告与逐项清单界定。

| 模块 | 已有可复用基础 | 实际缺口与完成条件 |
| --- | --- | --- |

| 笔记本管理 | ManagementTable、ImportPanel、版本视图 | 原 NotebookManager 有来源关联、检查更新、清单预检、草稿内容预览、发布与历史恢复。通用表格不能覆盖这些组合流程；需完整的发布与版本面板 |
| 用户与用户组管理 | MemberSearch、MemberAccess、UserProfile | DirectoryManager 和 UserDetails 的组成员增删、候选搜索、容量修改、管理员身份及授权明细仍需专门组合视图；权限判断及请求留在宿主 |
| AI 完整设置 | ChatPreferencesPanel、ModelSelector、SkillsPanel | 原 ChatSettings 包含 API 分组、模型增改删、协议、思考参数、图像设置、默认提示、工具默认值和导入导出。当前对话偏好仅覆盖模型、思考及联网选择 |
| 技能管理 | SkillsPanel | 目前为列表与启停；原 SkillsManager 的文件导入、名称/描述/正文编辑、删除及容量信息尚未完整抽取 |

| 锚点浮层 | Popup | 原 shared/FloatingPanel 是外部 anchor 控制的定位浮层。Popup 自带触发器，尚缺等价的受控外部锚点契约；FloatingWindow 属于拖动窗口，不能作为该文件的替代证据 |
| 富文本与阅读等价性 | MarkdownEditor、MarkdownContent、版本/冲突/补全组件 | 编辑核心、公式、Mermaid、表格、指令卡片和 Yjs 接口已经提供；原文档的全部指令、标题锚点、内联格式、专用内容以及保存导航、真实版本和块拖动仍需逐项比对。纯文件映射不能证明序列化及阅读等价性 |
| 画布编辑与实验参数 | CanvasWorkbench、GraphView、基础参数控件 | 原画布还有局部修改、诊断、版本接受、专用编辑器与录制视图；各学科实验的参数、验证和交互结构不同。需要抽取这些展示与控制层，计算和专用渲染引擎可由宿主保留 |
| 播放与课堂组合 | VideoPlayer、AudioPlayer、FloatingWindow、ClassroomTimeline | 常用局部快捷键与源解析接口已有；画中画、鉴权刷新、播放时间恢复、字幕、课堂笔记与讲稿的组合仍需真实内容验证 |
| 独立分享与发布提示 | MarkdownContent、文件树、工具栏、提示组件 | frontend/SharedPage 和 ReleaseNotice 不在原 277 项表内，需拆出分享导航、权限状态、引用与复制、章节目录和更新提示等组合视图 |

这些是已证实的能力差距；其余条目仍需按相同标准逐项对照，不能默认全部完成。逐文件表已将通用外壳、部分视图、宿主上下文与本轮专项验收分开记录。

## 后续逐项完成标准

1. 对照原文件列出可见区域、输入、回调、键盘、指针/触摸、权限、异步、错误恢复及窄屏行为。业务请求与计算可以保留宿主，但相关展示和控制必须有明确组件接口。
2. 使用真实的数据结构与内容类型构造演示；组件应能完成该任务的界面流程，不能仅在按钮点击后显示提示代替状态变化。
3. 用有代表性的任务测试验证关键行为与数据保留；通过深浅主题、不同产品色、窄容器、长文案和动态展开的浏览器检查。
4. 在课栈接入时验证真实鉴权、协作、保存、转换、流式消息和播放联动。这个阶段与组件本身的抽取及重新设计分别记录。
